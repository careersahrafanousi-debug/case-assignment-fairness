# Data Dictionary

All data is synthetic. Generated by `src/generate_data.py`, seed 8821.

## Fact table: `case_data` (15,908 rows)

One row per reportable case.

| Field | Type | Description | Notes |
|---|---|---|---|
| Case_ID | text | `CS-2026-NNNNNN` | Primary key. Unique after DQ-01 |
| Created_Date | datetime | When the case entered the system | Required; DQ-04 excludes nulls |
| Assigned_Date | datetime | When an analyst took ownership | Must be ≥ Created_Date (DQ-05) |
| Resolved_Date | datetime | When the case closed | Null unless status is Resolved (DQ-07, DQ-08) |
| Case_Type | text | One of six types | Joins `dim_case_type` (DQ-11) |
| Priority | text | Urgent / High / Standard / Low | Normalised for case and whitespace (DQ-02) |
| Current_Status | text | Resolved / In Progress / Pending Information | Anything else excluded (DQ-03) |
| Assigned_Team | text | `TEAM-01` to `TEAM-05` | Joins `dim_team` (DQ-09) |
| Assigned_Analyst | text | `AN-001` to `AN-035` | Joins `dim_analyst`; misses retained and flagged (DQ-10) |
| Routing_Method | text | Auto-Routed / Manual Triage / Analyst Self-Select | How the case reached its first analyst |
| Reassignment_Count | integer | Times the case changed owner | Valid 0–6; out of range nulled (DQ-12) |
| Documentation_Gap | text | Yes / No | Input to the complexity score |
| Policy_Exception | text | Yes / No | Input to the complexity score |
| Historical_Rework_Risk | text | Yes / No | Input to the complexity score |
| Reopened_Flag | text | Yes / No | Case reopened after closure (DQ-16) |

| SLA_Target_Hours | integer | Published target for the case type | Taken from reference data, not the record (DQ-15) |

Hours_Per_Analyst_Day.

**`dim_analyst` (35 rows).** Analyst_ID, Team_ID, Tenure_Band (0–1 yr, 1–3 yr,
3+ yr). No names. Analyst results are published only aggregated by tenure band.

**`dim_case_type` (6 rows).** Case_Type, SLA_Target_Hours, Typical_Touch_Minutes.
This is the authoritative source of SLA targets.

|---|---|
| Enrollment Change | 24 |

| Benefits Inquiry | 48 |

**`dim_date` (180 rows).** Date, Year, Month, Month_Name, Quarter,
Week_Of_Year, Day_Name, Is_Weekend. Calendar spine for time intelligence.

## Operational tables

**`team_capacity` (900 rows).** Team by day: Analyst_Count, Available_Hours,
Assigned_Case_Count, Average_Complexity, Open_Backlog, Backlog_Work_Hours. Supports the backlog days
of work measure.

**`team_workload` (5 rows).** The Workload Balance Index output, with each team's
cases handled, open cases, average complexity, index, status band, and the outcome
columns (SLA compliance, assignment accuracy, reopen rate, median resolution).

**`dq_exceptions` (577 rows).** Exception_ID, Rule_ID, Record_ID, Severity,
Description, Action_Taken.

# KPI definitions

## Case Complexity Score

A 0–100 weighted sum used to compare workload difficulty across teams.

| Component | Max | Rule |
|---|---|---|
| Case type weight | 30 | Coverage Termination 30, Claims Dispute 26, Authorization Review 22, Billing Correction 17, Benefits Inquiry 13, Enrollment Change 9 |
| Priority weight | 25 | Urgent 25, High 19, Standard 11, Low 5 |
| Documentation gap | 20 | 20 if a documentation gap was recorded, else 0 |
| Policy exception | 15 | 15 if a policy exception was required, else 0 |
| Historical rework risk | 10 | 10 if the case was flagged as rework-prone, else 0 |

**Bands.** Low 0–29, Moderate 30–54, High 55–74, Critical 75–100.

**Distribution.** Low 3,790 / Moderate 9,030 / High 2,771 / Critical 317.

**Validity.** The weights are analyst judgement. They were not fitted to
outcomes. The only evidence they are informative is that SLA compliance falls
monotonically across bands (68.58 → 62.69 → 56.07 → 50.00) and reassignment rate
rises monotonically (24.03% → 34.70%). That is enough to band work for comparison.
It is **not** enough to use the score as an automated routing rule, and it must
not be presented as a model.

**Edge cases.** An unmapped case type or priority would contribute 0 rather than
failing, but both are enforced by DQ-11 and DQ-02 so neither can reach the score.

## Workload Balance Index

```
Team Weighted Workload    = SUM(Complexity_Score for cases the team handled)
                            / (Analyst_Count x Hours_Per_Analyst_Day)
Workload Balance Index    = Team Weighted Workload / AVG(Team Weighted Workload)
```

**Bands.** Below 0.85 Underutilized, 0.85–1.15 Balanced, above 1.15 Overloaded.

**Values.** TEAM-01 1.190 Overloaded, TEAM-02 1.125 Balanced, TEAM-04 1.099
Balanced, TEAM-03 0.871 Balanced, TEAM-05 0.715 Underutilized. The five indices
average to 1.000 by construction.

**Scope decision.** The index uses every case the team handled in the period, not
only currently-open cases. An open-case version was built first and rejected: with
a 43-hour median resolution the open backlog is 194 cases across five teams, so
the index moved several tenths on single records. The period version is stable
because headcount was constant, but it cannot detect a short-lived spike — which
is why `backlog_days_of_work` is published next to it rather than instead of it.

**Interpretation warning.** This index measures workload per available hour. It
does not measure queue time, and TEAM-04 demonstrates why that matters: it is
inside the balanced band with the worst SLA of any team, because its problem is
8.74 days of queued work against an unachievable target, not volume per head.

## Assignment Accuracy Rate

```
Assignment Accuracy Rate = Cases Resolved Without Reassignment
                           / Total Cases With A Valid Reassignment Count
                           x 100
```

**Value.** 73.10% overall. By routing method: Manual Triage 83.83%, Analyst
Self-Select 77.69%, Auto-Routed 66.77%. By team: 72.22% to 73.81% — a 1.6 point
spread, which is the evidence that routing quality is a method property rather
than a team property.

**Denominator.** The 12 records with a reassignment count outside 0–6 are excluded
from the denominator rather than treated as zero reassignments, which would have
inflated the rate.

**Known overstatement.** Any reassignment counts as a miss. Legitimate escalations
are indistinguishable from misroutes because no reason code is captured (defect
D-01), so the true misroute rate is lower than 26.90% by an unknown amount.

## SLA Compliance Rate

```
SLA Compliance Rate = Resolved cases where Resolution_Hours <= SLA_Target_Hours
                      / Resolved cases
                      x 100
```

**Value.** 62.70% across 15,714 resolved cases. Always recalculated from dates;
the stored flag is ignored. Measured in elapsed clock hours, not business hours,
because the source has no business calendar (defect D-02). This biases compliance
downward, and not uniformly — case types whose volume skews toward Friday are
penalised more.

## Reopen Rate

```
Reopen Rate = Cases with Reopened_Flag = Yes / Total cases x 100
```

**Value.** 6.47%. Rises sharply with reassignment: 4.41% at zero reassignments,
12.15% at one.

## Backlog Days of Work

```
Backlog Days of Work = AVG(Backlog_Work_Hours / Available_Hours)
```

**Values.** TEAM-04 8.74, TEAM-02 8.48, TEAM-01 6.91, TEAM-05 3.27, TEAM-03 2.65.
Published alongside the Workload Balance Index because it captures the queue-time
dimension the index misses.
